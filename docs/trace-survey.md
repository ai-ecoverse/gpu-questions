## How often agents ask

In interactive sessions, **568 of 5,559 end-of-turn messages (10.2%)** end with a question to the user. The rate varies by agent: codex 20%, droid 16%, opencode 24%, claude-code 7%, cursor-acp 3%, and grok 0.4%.

Heuristic class breakdown:

| Class          | Count | Notes                                              |
| -------------- | ----- | -------------------------------------------------- |
| yes_no         | 331   | Dominated by "Want me to …?"                       |
| either_or      | 129   | Often "Want me to X, or Y?"                        |
| multi_choice   | 43    | Numbered or lettered list followed by a question   |
| multi_question | 26    | Several questions in one message                   |
| open_wh        | 14    | Few true open questions in interactive sessions    |
| confirm_plan   | 10    | "Shall I proceed?"                                 |
| other          | 15    |                                                    |

In 112 of the yes/no cases, a bullet list comes before the question. The list is status or context, not options. This is the main false-positive trap for list-based option extraction.

## Free gold: structured ask-tool calls

There are **191 calls holding 295 questions** already in `{question, options[]}` form:

| Tool                                        | Schema                                                                        | Calls |
| ------------------------------------------- | ----------------------------------------------------------------------------- | ----- |
| Claude Code `AskUserQuestion`               | `questions[{question, header, multiSelect, options[{label, description}]}]`   | 62    |
| Droid `AskUser`                             | text `questionnaire` with `[question]`, `[topic]`, and `[option]` lines       | 66    |
| bb-bridge `AskUserQuestion` (Droid, Cursor) | Claude schema; BB `pending_interactions` stores `ask-user-question`           | 49    |
| Cursor `AskQuestion`                        | `questions[{id, prompt, options[{id, label}]}]`                               | 12    |
| opencode `question`, Copilot `ask_user`     |                                                                               | 2     |

Across these questions, **3 options is the mode** (174 questions), followed by 2 (70) and 4 (50). 130 questions offer a "(Recommended)" option, which is almost always listed first. Only 4 are multi-select.

These tool calls can't train a free-text tagger directly, because their text was never prose. They still help in three ways:
- They show which **options agents choose to offer** for a given prompt.
- They show the **answer distribution**: 60 structured answers, 43 free-text or "Other" answers, and 11 cancelled.
- They can be **rendered back into prose** ("Want me to A, B, or C? I'd go with A."). This gives exact span labels, the same way gpu-time's slot generator does.

## What users actually reply

Of the 568 end-of-turn questions:

| Reply                                        | Share |
| -------------------------------------------- | ----- |
| Short "yes", "ok", or "go"                   | 7%    |
| Starts with "yes" and adds instructions      | 13%   |
| Negation, option pick, or exact option label | 5%    |
| Medium or long free text                     | 46%   |
| Short but not a clear answer                 | 19%   |
| No reply (session ended)                     | 10%   |

A preset choice button fully replaces the reply only about 16% of the time. Pre-selected options should therefore **prefix an editable reply**, not replace the text box.

## Pitfalls for dataset building

- **Secrets:** at least one reply contained a live-looking API key. Scrub credentials and emails from questions and replies before anything leaves `data/`.
- **Automated sessions:** exclude subagent, reviewer, and orchestrator sessions (16k end-of-turn messages, mostly rhetorical or open questions with machine "replies"). They are detected via `isSidechain`, `callingSessionId`, `session_meta.source`, and Augment prompt prefixes.
- **False positives:** remove question marks inside code, URLs, and rhetorical "Why? Because…" patterns before labeling.
- **Mislabeled "or":** wh-questions that contain "or" are really either_or.
- **Over-splitting:** splitting options on "or" and commas breaks some options in two ("with a tool or language"). A learned span tagger fixes this and regex does not.
